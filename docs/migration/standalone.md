# Standalone migration notes

Agentscrape intentionally uses its own package name, executable name, state directories, service label, user-agent, capture-session prefix, and extraction-envelope identity. Envelope schema version `1` is retained, while `extractor.name` is `agentscrape`.

Safe offline command shapes and defaults remain compatible: preset inspection, corpus replay, HTML conversion, recorded feed discovery, output flags, selector/session/media options, and queue inventory preserve their established stdout/stderr roles. Recorded feed parsing remains `agentscrape discover-feed FILE --source-url URL`, including repeatable `--page URL FILE` inputs. The command now spells its full shape as `agentscrape discover-feed [FILE] --source-url URL`: omitting `FILE` selects bounded, direct live transport, while more than one positional is a usage error. `--etag` and `--last-modified` remain recorded validators with `FILE` and become conditional request headers in live mode. Direct `feed` mode binds them to the source URL; `auto` mode requires `--validator-url` and sends them only to that exact response URL. `--format` is accepted before the command and on commands where it is a compatibility no-op. Agent-oriented help is available through `--agent-help`, `--agent-teaser`, and hidden JSON help through `--help-json`.

Intentional behavior differences are hardening changes: parser and option mistakes exit 2, cancellation is signal-aware, recursive HTML conversion does not follow symlinks or overwrite Markdown, executable local content handlers require explicit in-process TypeScript registration, and queue runtime resolution is explicit as `AGENTSCRAPE_DATA_HOME` first, then `${XDG_DATA_HOME}/agentscrape`, then `~/.local/share/agentscrape`. Live feed discovery has no browser or predecessor-network fallback: HTML auto mode requires an explicit typed alternate feed link, and configured archive selectors are the only HTML entry parser. Its HTTP(S)-only transport bypasses ambient proxies, revalidates DNS and redirects, pins a public resolved address to each connection, and enforces bounded identity-encoded fatal-UTF-8 responses. The installed standalone wrapper exports its resolved private data root so interactive and LaunchAgent invocations stay aligned. It now executes an exact archived commit snapshot under `~/.local/state/agentscrape/runtime/<sha>`, with production dependencies and a sealed inventory manifest, rather than a mutable checkout. The verifier is required in and materialized from the exact Git commit; dirty or snapshot-selected helper bytes are never trusted, and publication uses a native atomic no-replace rename. Reinstall/uninstall share one fail-closed lock under the normalized HOME regardless of state-directory overrides; command and LaunchAgent overrides must remain within that HOME boundary. `HOME` and installer-created private directories require the current uid and reject writable or special modes. Exact historical 8-line and 12-line checkout receipts can migrate only while their exact source checkout and commit tree remain available and agree with the current checkout's Git authority. A catchable cutover failure restores the exact correlated checkout-backed public bytes captured before mutation; it does not fabricate a snapshot for a predecessor commit without the runtime helper. The new installer uninstalls checkout-backed evidence only from its owning checkout when that commit contains the authenticated helper; a helperless predecessor fails closed before mutation. Uninstall requires exact snapshot-backed public bytes, unloads the exact service, removes only revalidated command/plist/receipt/deployed-SHA paths, and syncs their parents. Public expected-absent slots use native no-replace publication, while replacement of an owned slot requires its classified device/inode immediately before rename. The tiny check-to-rename gap against an actively malicious same-UID process remains outside the claimed boundary. Published snapshots are retained on reinstall and uninstall; cleanup is deferred to ASR25. Snapshot modes and repeated hash checks are corruption evidence, not a same-UID malicious immutability claim. There is no process-death or power-loss self-healing: interrupted mixed public state other than conservative C fails closed and needs an explicit rerun or manual cleanup, without deleting foreign or ambiguous evidence.

Corpus capture is also runtime data now: the default is the configured data home's `corpus/` directory. Omitted-root replay runs shipped fixtures first, then a secure physically distinct configured overlay with `captured/` labels. Explicit API roots remain single-root operations. No predecessor executable, state, service, or configuration is imported automatically.
